# 路线图

按**从基础核心闭环到智能监督**的顺序推进。
先把「常驻采集 + 今日任务配额计时与到点提醒」做扎实，再在真实使用数据的基础上微调「跑偏检测与高频切换提醒」的判定逻辑。

---

## 阶段 1：混合采集（Alma + AX 标题补齐）+ 菜单栏配额仪表盘 + 到点提醒（当前优先）

**目的**：解决 `alma-time-audit` 只能次日复盘、且原有采集缺少窗口标题的问题，在当天跑通「读取 Alma 实时流并补齐窗口标题 → 设定各事项今日保底/封顶时长 → 菜单栏高密度仪表盘实时展示 → 配额到点右上角轻提醒换挡」的完整闭环。

### 做什么

- **双通道混合采集层（`DayHelmCapture`）**：
  - 增量拉取 `http://localhost:23001/api/activity-recorder/sessions` 的今日实时 `sessions` 与 `events`（重启不丢当天数据）
  - 2s 轮询 `NSWorkspace` + Accessibility (`kAXTitleAttribute` / `AXDocument`)，补齐 Alma 缺失的窗口标题与浏览器 URL（含敏感过滤）
  - 当 Alma 未运行时自动无缝退化为纯本机采样
- **任务配额与分析引擎（`DayHelmCore`，纯逻辑，测试先行）**：
  - 支持配置每日各事项的保底目标（`targetMinutes`）与封顶上限（`capMinutes`）
  - 声明当前专注事项后，只要人在场，跨多应用协同操作均累计入当前事项
  - 实时生成今日时间光谱条（`Day Spectrum Ribbon`）数据与连续块/切换频次指标
- **Precision Telemetry 菜单栏仪表盘与非抢占提醒窗（`DayHelmApp`）**：
  - 顶部菜单栏实时胶囊（如 `● 电商做深 · 52/90m`）
  - `330pt` 免滚动高密度下拉面板：当前专注盒 + 一键切任务胶囊 + 双向配额进度条 + 今日时间光谱条 + 底部三格微指标
  - 配额到点时，右上角滑出 `.nonactivatingPanel` 轻量卡片（不抢键盘焦点），提醒换挡或 `+15m 收尾`

### 不做

不在阶段 1 做复杂的"自动判定跨项目跑偏"弹窗（先把融合了窗口标题的真实活动流和显式专注时段落盘到 `~/.config/alma/dayhelm/`，用来观察真实的多应用切换模式）。

### 验证门槛

- 判定层与配额计时逻辑有完整单测（注入假时钟）
- 自己日常真用 3–5 个工作日：
  - 菜单栏能随时看清今天每个事项做了多久、还差多少
  - 到点提醒能有效帮自己在运营类事务上及时刹车，去处理别的事
  - 资源占用极低，无烦人误报

## 阶段 2：项目映射、跑偏检测与高频切换监督

**目的**：在阶段 1 积累了几天真实「声明事项 vs 实际应用/标题/URL」数据后，加上智能监督提醒——当做着 A 不知不觉飘去 B、或者陷入高频乱切时，及时拉回来。

### 前置

阶段 1 跑通，且已经根据阶段 1 的真实采集样本讨论确定了项目映射与跑偏判定的交互细节。

### 讨论与设计要点（阶段 2 开始前拍板）

1. **项目映射机制**：
   - 如何复用 `~/.config/alma/time-audit/config.json` 的项目关键词？
   - 如何定义「明确属于另一项目」vs「中性辅助工具（Finder、预览、无特定标题的编辑器/表格）」？
2. **跨项目跑偏提醒逻辑**：
   - 滑动窗口多大（例如连续 3–5 分钟命中另一项目特征）才算跑偏？
   - 提醒卡片交互：一键「切回原事项」vs「顺势把当前专注切换为新事项」vs「只是顺手看一眼（静音 N 分钟）」。
3. **高频切换（碎片化）提醒逻辑**：
   - 如何区分「做电商时在抖店、1688、表格之间正常的快速配合」与「注意力涣散时的烦躁乱切」？

### 验证门槛

- 连续使用 5 个工作日，跑偏/乱切提醒的准确率高（每天误报 ≤ 2 次）
- 收到提醒后能真正帮助自己回到原事项或显式切换任务，而不是机械点掉

## 阶段 3：与 `alma-time-audit` 联动及上下文恢复优化

**目的**：让当天的专注记录反哺次日审计，并降低任务切换时的上下文丢失成本。

### 做什么

- **切换事项时的简短备注（「刚才停在哪」）**：换挡或被打断时可顺手记一句，下次切回该事项时展示
- **与 `time-audit` 数据联通**：将 `~/.config/alma/dayhelm/days/*.json` 中的显式专注时段与补齐的 `windowTitle` 提供给 `time-audit`，解决跨多应用干活时次日日报归因不准（53% 归属率）的问题

---

## 阶段 4（可选）：对外可见的专注状态

**目的**：减少外部打断（仅当数据显示有一部分切换来自外部消息打断时才做）。

可选形态：进入专注事项时自动同步状态、菜单栏图标颜色变化等。

---

## 明确不做（长期排除）

| 项 | 理由 |
|---|---|
| 单次 Cmd+Tab 强制拦截 / 全屏 15s 读秒锁 | 多应用协同场景下误报率极高，违反轻量原则 |
| 应用白名单自动最小化/隐藏其它窗口 | 同一应用（如浏览器/IDE）承载多个项目，按应用封锁不可行 |
| 扛强杀会话锁 | 定位是监督与提醒，不是强制锁机 |
| 跨设备同步 / 云备份 / 账号 / 移动端 | 单人本机使用，保持极简 |
| 游戏化 / 生产力评分 | 已有 time-audit，不重复造 |
