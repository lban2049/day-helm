# 产品需求

## 问题定义

用户已经能准确知道"时间花在哪些项目上"（`alma-time-audit` 已实现），真正的问题在更下面一层：

> **知道该做什么，也坐到了电脑前，但每隔几分钟就换个东西看——一天结束，重要的事只推进了十几分钟。**

这个问题有三层，本工具只解决后两层：

| 层 | 内容 | 现状 |
|---|---|---|
| 知道时间花在哪 | 项目级时长归因 | ✅ 已由 `alma-time-audit` 解决 |
| **保持连续投入** | 不被切碎的 ≥12 分钟工作块 | ❌ 本工具目标 |
| **保证重要任务配额** | 今天"电商做深"是否达到 90 分钟 | ❌ 本工具目标 |

## 目标用户

单人，就是用户本人。macOS 26，Apple Silicon。偏好可自己改的工具，愿意读源码和改配置。

## 用户故事

### 必须有（P0）

**US-1｜开始一段专注**
> 我要能一句话说清"这一段要产出什么"，然后进入专注状态。中途想切走时，这句话会被摆回我眼前。

验收：
- 开始前必须填「交付物」（一句话）和「归属项目」
- 项目从 `focus.json` 的 `primary_focus` 读取，可覆盖但需显式选择
- 未填写无法开始

**US-2｜切走时被打断一下**
> 我按 Cmd+Tab 切到别处时，希望有个东西拦我半秒到十几秒，让我意识到自己在换任务。

验收：
- 检测到前台应用切出允许范围 → 显示全屏浮层
- 浮层内容只有三样：当前交付物、`继续原任务`、`记录中断并离开`
- **不写任何说教文案**（实证：说教无效，只有"可取消"和"延迟"有效）
- 选择"记录中断"后有最短等待（初值 15 秒），等待结束才能继续操作
- 浮层本身不得盖住菜单栏以外还挡不住的东西时要诚实说明（见 architecture）

**US-3｜看见今天的真实状态**
> 我想随时一眼看到：现在这个块多久了、今天最长块多长、今天切换了几次。

验收：
- 菜单栏常驻，点击展开
- 主屏只有四个数：当前块时长 / 今日最长块 / 今日切换次数 / 每小时切换
- 不显示"生产力评分"（避免与 time-audit 冲突）
- 不显示"已完成 N 个番茄"

**US-4｜知道重要任务还差多少**
> 我要看到今天"电商做深"投了多少分钟，离配额还差多少。

验收：
- 配额来自 `focus.json` 的 `primary_focus`，本工具只读不写
- 只显示**缺口**，不显示"已完成 N 分钟"的成就感式呈现
- 配额达成后可配置是否解除摩擦

**US-5｜中断后能接上**
> 被打断回来时，我要立刻知道刚才停在哪、下一步是什么。

验收：
- 中断时可 3 秒内记一句「我停在哪 / 下一步」（可跳过，但跳过会被计数）
- 恢复该任务时，顶部显示上次记录的那句
- 有全局热键：一句话存进"未处理"清单而**不切走**

### 应该有（P1）

**US-6｜白名单模式**
> 专注时只允许几个应用在前台，切到别的会被最小化并记录。

验收：允许 1–3 个 app；越界应用被隐藏（不 kill）；可申请临时放行（如 15 分钟额度）并记录。

**US-7｜数据能被 time-audit 读取**
> 次日的时间审计能用上更细的项目归属。

验收：产出格式稳定、有 schema 版本、有文档；time-audit 侧改动由 time-audit 项目负责。

### 不做（明确排除）

| 不做 | 理由 |
|---|---|
| 网站/App 黑名单拦截 | 用户的切换发生在正当工作之间，黑名单全部放行 |
| 跨设备同步 | 所有同类产品的差评第一来源。单机自建，风险归零 |
| 日历集成 | 同类产品的 bug 热点 |
| 内置任务管理器 | 只做"今天"，不做待办管理 |
| 游戏化（种树/宠物/房间） | 对"两个正事之间切换"无效 |
| 生产力评分 | 与 time-audit 重复且口径会冲突 |
| 番茄钟的固定 25/5 节律 | 实证无生产率优势，且疲劳更快上升 |
| 白噪音 / 音景 | 与目标无关 |
| 屏幕截图 / OCR | 已由 local-screen-time-journal 与 Alma recorder 承担 |

## 成功标准

不设"专注时长"这种结果指标，只设**过程指标**，因为过程可控：

| 指标 | 当前基线 | 阶段 1 目标 | 阶段 2 目标 |
|---|---|---|---|
| session 中位时长 | 4.1 分钟 | 8 分钟 | 12 分钟 |
| 每日 ≥12 分钟的块数 | 未统计（约 1–2） | 3 个 | 5 个 |
| 切换到"非白名单应用"次数/小时 | 未统计（总切换 50–78） | 建立基线 | 下降 30% |
| 主攻方向（电商）当日投入 | 波动大，常见 <30 分钟 | 有可见缺口 | 稳定 ≥ 90 分钟 |

**不做的事情之一：不追求 25 分钟。** 从 4 分钟直接到 25 分钟只会制造连续失败感。

## 未决问题

1. 摩擦时长初值 15 秒是否合适？→ 阶段 0 原型实测决定
2. 浮层用全屏还是角落小窗？→ 阶段 0 原型实测决定（全屏可能过于激进）
3. 会话锁要做到"扛强杀"吗？还是自用场景下"重启后可恢复"就够？→ 需要 ADR
4. 白名单里"允许的应用"要不要包含浏览器？（用户的工作大量在浏览器里完成，但浏览器也是切换的主要入口）→ 需要 ADR
5. 配额未达成时是否要在当天晚间主动提醒？会不会变成新的打扰？→ 阶段 2 再定
