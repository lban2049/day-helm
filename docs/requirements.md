# 产品需求

## 问题定义

用户已经能通过 `alma-time-audit` 在**第二天**知道"昨天时间花在哪些项目上"，但事后复盘解决不了**当天当下**的三个问题：

> 1. **做一件事时不知不觉飘去别的事**：多项目并行时，经常在处理 A 的过程中切去看 B，或者陷入高频来回切换，等意识到时半天已经过去了。
> 2. **单一事务耗时失控或重要事务投入不足**：比如电商日常运营不知不觉花掉几个小时，挤占了本该做核心推进或其它任务的时间；或者重要任务到晚上才发现今天只干了十来分钟。
> 3. **单任务天然需要跨多应用切换**：处理电商等实际业务时，必然要在浏览器、图片工具、表格、终端等多个应用间切换。**传统的"应用黑名单/白名单锁死"根本无法判断我是在正常干活还是切走了**，强行拦截只会制造大量误报。

因此，本工具的定位是**当天的轻量级实时监督与配额提醒器**：

| 层 | 内容 | 现状与分工 |
|---|---|---|
| 事后审计与评分 | 次日分析昨天的时间去向与问题 | ✅ 已由 `alma-time-audit` 解决 |
| **当日任务配额追踪（保底与封顶）** | 实时看见各任务今天已专注多久、离目标还差多少、是否已到上限该换挡 | 🎯 **本工具核心目标** |
| **当日跑偏与碎片化监督** | 常驻后台采集，在检测到明显跑偏或高频乱切时，温和提醒回到当前专注事项 | 🎯 **本工具核心目标** |

## 目标用户

单人，就是用户本人。macOS 26，Apple Silicon。偏好轻量、不折腾、可自己改的工具。

## 用户故事

### 必须有（P0）

**US-1｜设定今日各事项与双向配额（保底 / 封顶）**
> 我可以在界面内直接维护今日要推进的事项清单，只需填写事项名称、一句话说明（可选，供自动识别参考）与当日保底目标或封顶上限（如 30 / 45 / 90 / 120 分钟），无需手动维护复杂的关键词与域名规则。

验收：
- 支持直接在独立设置窗口内完成**完整事项管理（CRUD）**：新增事项、编辑名称/短名/一句话说明（`description`）/颜色/可选高级匹配规则、上下调整排序、删除事项，并持久化到 `~/.config/alma/dayhelm/config.json`
- 支持为每个事项开关并设定当日 **保底目标（`targetMinutes`）** 与 **封顶上限（`capMinutes`）**，提供**滑块拖动（Slider）+ 直接数字输入（TextField）**双模联动控件
- 初次运行（尚无 `dayhelm/config.json` 时）可从 `~/.config/alma/time-audit/` 只读初始化项目配置，本工具不写外部配置；一旦用户在 DayHelm 内维护了自定义清单，以 `dayhelm/config.json` 为准
- 菜单栏可随时查看今日各事项的「已投入时长 / 目标时长」进度

**US-2｜低干预自动归属与实时菜单栏展示（支持一键纠偏）**
> 开启智能自动识别（Jev）后，我无需反复手工点选「我现在在做什么」：工具会自动根据当前窗口、近期上下文与脱敏 OCR 摘要判断我当前所处事项（包括计划事项、其他事务与分心/休息），自动累计时长，并在顶部菜单栏以文字标签实时展示当前事务类型与已用时长；若关闭该开关或离线，仍支持手动一键切换与本机规则。

验收：
- 设置中提供「启用 Jev 智能自动识别」开关（默认关闭）；开启且未配置 `JEV_API_KEY` 时明确提示用户配置 API Key（支持界面内保存与连通性测试，亦兼容环境变量 / `.env`）
- 开启且 Key 有效时自动归属当前事务（无需手工弹窗确认），经置信度与迟滞防抖后自动切换并累计时间；跨应用协同（如浏览器 ↔ Photoshop / Excel / Terminal / Finder）自然归属到同一事项
- 顶部菜单栏默认实时显示文字标签与时长（如 `电商做深 42/90m`、`其他事务 12m`、`分心中 6m`）
- 菜单栏 Popover 中仍可一键点选任一事项作为即时纠偏（并记忆当日该上下文归属），也可一键恢复自动追踪或暂转休息

**US-3｜配额到点提醒（防止在单一事项上耗尽时间）**
> 当某个事项达到了今天设定的专注时长（尤其是日常运营这类需要控制时间的事项），工具要提醒我时间到了，可以收尾去处理别的事情。

验收：
- 当当前专注事项累计达到设定时长时，弹出清晰的提醒卡片
- 提供快捷操作：如 `切换去做别的事`、`再延 15 分钟收尾`、`今日不再提醒该项`
- 状态栏清晰标记该事项今日已达标/已到上限

**US-4｜跑偏与高频乱切提醒（监督回到专注事项）**
> 当我声明在做 A 事项，但后台常驻采集探测到我已经切走去干别的、或者又开始高频频繁切换时，提醒我回到正事或显式切换任务。

验收：
- **不锁死屏幕、不拦截单次 Cmd+Tab**，避免干扰正常的多应用操作
- 在两类趋势信号下触发温和提醒（具体判定规则与交互在后续阶段细化）：
  1. **疑似跑偏**：持续一段时间停留在明显与当前专注事项无关的其它项目/内容上
  2. **高频切换（碎片化）**：短时间内窗口/应用切换频率异常升高，无法形成连续投入
- 提醒时允许用户一键选择：`回到原专注事项`、`将当前专注切换为新事项`、或 `暂时忽略（顺手处理一下）`

**US-5｜看见当天的实时状态看板**
> 我不用等到第二天看日报，今天随时点开菜单栏就能看到各任务的进度和专注连续度。

验收：
- 菜单栏常驻，点击展开
- 显示：当前专注事项及本次已持续时长、今日各事项配额进度、今日切换频次 / 最长连续块
- 不显示"生产力评分"（避免与 time-audit 冲突）
- 不显示"已完成 N 个番茄"

### 应该有（P1）

**US-6｜切换/中断时的简短上下文留存**
> 当一个事项到点换挡，或被动打断切换到别的事情时，可以顺手记一句「刚才停在哪 / 下次从哪接上」。

验收：切换事项时可选填一句话备注（可跳过，不强制阻塞）；下次切回该事项时展示上次留下的备注。

**US-7｜数据能被 time-audit 次日读取**
> 当天显式声明的专注时段与常驻采集记录，能作为次日 `time-audit` 的补充信号（提升多应用切换下的项目归属准确度）。

验收：产出格式稳定、有 schema 版本、有文档；`time-audit` 侧改动由 `time-audit` 项目负责。

**US-8｜独立原生录制、可选屏幕 OCR 与开放 Agent 数据中心**
> 即使完全退出 Alma，DayHelm 也能独立完成毫秒级活动事件、AX 窗口标题、URL、去重屏幕快照与设备端 Vision OCR 录制，并通过开放 SQLite（`activity.sqlite`）、CLI（`query`/`search`/`sessions`/`status --json`）与本地兼容 HTTP API（`127.0.0.1:24001`，`24001...24009` 空闲选端，绝不占用 Alma 的 `23001`）向任意 AI Agent 与 `alma-time-audit` 开放。

验收：
- 屏幕录制权限可选可开关；未授权或关闭时无痛降级为 AX 标题 + URL + 事件录制
- 命中 `PrivacyRedactor` 脱敏规则或锁屏时绝不截屏、不运行 OCR、不调用浏览器 AppleScript
- 浏览器支持 Chrome / Safari / Safari Technology Preview / Arc / Dia 等，支持 `AXDocument` + 隐私受控的 AppleScript 标签页 URL/标题兜底
- 支持 `dayhelm query` / `dayhelm search` / `dayhelm sessions` / `dayhelm status --json`（`json` 与 `md` 输出）以及 Alma 形状的 `/api/activity-recorder/status`、`/permissions`、`/config`、`/sessions`（含 `offset`/`analysisStatus`）、`/sessions/<id>`（含 6 位以上前缀匹配）、`/sessions/<id>/events`、`/search/keyword`（FTS5 trigram）、`/snapshot-file`、`/summary/daily|weekly`、`/digest`、`/report/<dateKey>` 与 DayHelm 自有的 `/api/dayhelm/context`、`/api/dayhelm/search`
- 会话级暴露聚合敲击密度（`clickCount` / `keypressCount` / `inputEventsPerMinute`），只计次、不读按键内容与坐标；支持分级降采样与磁盘总上限保护
- 在独立原生窗口（从菜单栏面板入口打开，保持主 Popover `330pt` 免滚动）中提供符合 DayHelm Precision Telemetry 风格的 **Activity Recorder 配置与历史会话检视器**：支持总开关与存储配额进度条、macOS 权限检测与跳转、采集防抖/心跳/空闲阈值/输入停顿/画面轮询/JPEG 质量调节、Vision OCR 开关与语言/采样间隔、全局键鼠监听开关、敏感应用 Bundle ID 列表配置，以及可检索的采集历史会话列表与事件/快照/OCR 详情检视

**US-9｜按天确定性统计报表与本地 Agent 分析提示词**
> 我可以在独立窗口的「每日统计」中随时翻看昨天及历史任意一天的客观时间去向、专注连续度、分时节律与切换路径，并与近 7 日均值基线做轻量对比；所有历史单日统计均由后台任务每天自动预计算并持久化，切换 Tab 或日期秒开不卡顿；同时能一键复制包含当日统计骨架与只读查询指令的本地 Agent 分析提示词，直接交给 Claude Code / Codex / Hermes 做深度复盘或日报草稿，无需额外配置 AI API Key 或导出数据到网页端。

验收：
- **后台预计算与秒开体验（不实时计算当天）**：由后台低优先级任务在跨天与启动时自动扫描并计算**前一天及之前缺失的历史日期**（严格 `< 今天`），将结果持久化到 `~/.config/alma/dayhelm/stats/YYYY-MM-DD.json`（幂等不重复计算，不处理当天）。UI 切换到「每日统计」Tab 或切换日期时仅异步读取已持久化报表（若后台尚未生成则展示非阻塞加载占位并在完成后自动刷新），默认定位到最近一个有数据的历史日期（通常为昨天），无历史数据时展示清晰引导，绝不阻塞主线程。
- **纯本地确定性统计（无新增 AI API Key、无主观“生产力评分”）**：单日统计指标（时间分配、光谱段、连续块、跨任务切换）以 `days/YYYY-MM-DD.json`（及历史日期会话补全）为单一真源，输入密度与会话/会议/快照/OCR 计数由 `activity.sqlite` 按日补齐，自动读取前 7 天历史统计/归档计算 `baseline7d` 均值微对比
- **完整单日多维看板**：支持翻看历史已分析任意一天（`< 前一天` / 日期下拉 / `最新一天` / `后一天 >` / 可选异步后台重算），展示 4 格核心遥测卡（含总活跃时长与起止跨度、中位/最长连续块、有效跨任务切换与乱切、键鼠输入密度与会话/会议/快照/OCR 计数）、放大版日时间光谱条、事项配额与 6 大活动大类分布、Top 应用 / Top 浏览器站点排行（剥离 `www.`、保留非默认端口、`redacted == true` 绝不入榜）、24 小时分时活跃/切换/乱切节律图（支持悬停看单小时详情）、5 档连续停留时长分布（`<1m`、`1–3m`、`3–10m`、`10–25m`、`≥25m`）及高频切换路径 Top N（`A → B` 频次与切入后平均停留秒数）
- **本地 Agent 深度分析提示词**：提供「每日复盘与习惯诊断」「工作产出与日报草稿」两套场景预设，动态注入所选历史日期、本地文件目录（`stats/YYYY-MM-DD.json` / `days/YYYY-MM-DD.json` / `activity.sqlite`）、推荐的 `dayhelm` CLI 下钻命令（`stats` / `sessions` / `search`）与 `sqlite3 -readonly` 只读示例、当日轻量统计骨架及只读与隐私脱敏护栏；支持展开只读预览与一键复制到剪贴板（不提供网页版粘贴数据导出）
- **CLI 与 UI 共用聚合器**：支持 `dayhelm stats [--date YYYY-MM-DD] [--rebuild] [--format json|md] [--json] [--store-dir <path>]`，未传 `--date` 时默认读取最近历史日期；历史日期优先直读已落盘 `stats/YYYY-MM-DD.json`（缺失时按需计算落盘，`--rebuild` 可强制重算）
- **严格隐私隔离**：命中 `PrivacyRedactor`（`redacted == true`）的记录绝不泄露窗口标题或域名至 Top 站点、切换路径、`stats/*.json` 或 Prompt 骨架

### 不做（明确排除）

| 不做 | 理由 |
|---|---|
| **强制锁死切换 / 全屏 15 秒读秒遮罩** | 处理单任务时天然要跨多个应用，强制拦截无法准确区分"正常协同"与"分心切走"，极其烦人 |
| **应用级白名单隐藏/最小化** | 同上，浏览器和编辑器里承载了所有项目，按应用封锁不可行 |
| **扛强杀会话锁** | 工具定位是"实时监督与提醒助手"，不是跟自己对抗的监狱 |
| 网站/App 黑名单拦截 | 用户的切换发生在正当工作之间，黑名单全部放行 |
| 番茄钟的固定 25/5 节律 | 实证无生产率优势，且与"按任务每日配额推进"的目标不符 |
| 跨设备同步 / 云备份 | 单机自建，风险归零 |
| 日历集成 / 内置复杂待办管理 | 只管"今天这几个专注事项的配额与监督" |
| 游戏化（种树/宠物/房间） | 对多任务管理无效 |
| 生产力评分 | 与 time-audit 重复且口径会冲突 |
| 统计看板内嵌 AI API Key 调用 / 网页版 AI 粘贴导出 | 统计层保持 100% 纯本地确定性；深度复盘通过提示词指引本机 Agent 只读下钻 |
| 周/月趋势大盘（当前阶段） | 本阶段聚焦单日精准归因与近 7 日均值微对比 |

## 成功标准

| 指标 | 当前基线 | 阶段 1 目标（配额与看板） | 阶段 2 目标（接入跑偏/到点提醒） |
|---|---|---|---|
| 当日任务配额可见性 | 0（只能次日 08:00 看日报） | 菜单栏实时可见各任务进度 | 核心任务达标率提升，运营类任务不严重超时 |
| session 中位时长 | 4.1 分钟 | 建立实时连续块基线 | 提升至 8–12 分钟 |
| 活跃日每小时切换次数 | 50–78 次/小时 | 实时可见当前切换热度 | 高频乱切时段收到提醒后能收敛，日均下降 20–30% |
| 工具自身打扰度 | — | 无弹窗打扰 | 每日提醒次数合理、不因烦人而想关掉工具 |

## 待细化问题（后续逐步讨论确定）

1. **项目映射与跨项目跑偏如何检测？**
   - 当用户声明在做「电商」时，必然会用到通用工具（无特定标题的浏览器页面、图片处理、本地文件夹等）。如何设计「明确属于其它项目」vs「中性/辅助工具」的映射规则？
   - 连续偏离多久（如 3 分钟 vs 5 分钟）才算跑偏并触发提醒？
2. **不同专注事项之间的切换交互怎么最顺手？**
   - 是完全靠菜单栏手动点选切换，还是在检测到已持续操作另一项目时弹窗一键问「要不要把当前专注切到 X」？
   - 如果忘了点"开始专注"就开始干活，是否需要自动探测提醒开启？
3. **高频切换（碎片化）的阈值怎么定？**
   - 在正常跨应用干活（比如在抖店和表格之间复制数据）时，也会有高频切换。如何区分「围绕同一件事的多应用高频配合」和「无目标的烦躁乱切」？
4. **提醒的视觉形态**
   - 跑偏提醒与配额到点提醒，是用屏幕右上角轻浮窗（不抢键盘焦点）还是居中提醒卡片？
